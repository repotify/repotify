<h3 align="center">成千上万的代理技能，只挑适合你仓库的。</h3>

<p align="center">Repotify 读取开发者和 AI 公司在 GitHub 上发布的代理技能，按用途分类、检查风险，<br>并把最适合你项目的技能安装到 Claude Code、Cursor、Codex 或 Gemini CLI 中。</p>

<p align="center"><a href="../../README.md">English</a> · <a href="README.tr.md">Türkçe</a> · <b>简体中文</b></p>

## 开始使用

在项目文件夹中运行：

```bash
npx -y @repotify/repotify@latest
```

或者直接告诉你的代理：**"为这个项目配置 Repotify：https://github.com/repotify/repotify"**

<p align="center"><img src="../../.github/assets/demo.svg" alt="终端中的 Repotify：读取项目，为每项工作推荐一个条目，排除 react-native-skills，然后安装所选条目" width="100%"></p>

## 工作原理

1. **读取。** 只查看清单文件、文件名，以及这台电脑装有哪些运行环境。你的代码不会被读取，也不会被发送到任何地方。
2. **询问。** 只问那些答案会改变推荐结果的问题：最多三个，常常一个也不问。每个问题只问一次。
3. **挑选。** 每项工作挑一个最好的技能、MCP 服务器或工具。目录中的每个条目都通过了安全扫描，并由一个决策模型分类。来自爬取的条目只有在有证据表明确实有人在用时才会进入默认集合，否则只作为备选列出。
4. **安装。** 每个技能来自固定的提交，校验哈希，并在你的电脑上再次扫描。钩子和 MCP 服务器在你开启之前保持关闭。
5. **跟进。** 两个可选的钩子让这套配置在第一天之后继续发挥作用：跟踪器和路由器（见下文）。

## 看见决策过程

`repotify ui` 在你自己的电脑上打开一个页面，把目录画成一棵树。橙色表示仍在候选，绿色表示已选中；你每回答一个问题，就确定一条分支，最后只剩下被选中的条目。这个页面只读，不能安装或修改任何东西。

<p align="center"><img src="../../.github/assets/ui.gif" alt="repotify ui：目录画成一棵树。一开始整个目录都在候选；项目文件和三个回答把它缩小到最终的选择" width="100%"></p>

## 安装之后

- **跟踪器**（会话开始时运行的钩子）记住项目展示过哪些技术栈和需求。当你加入新东西（比如一个支付库）时，它会告诉代理一次：现在有哪些新的选择适合。它每周还会检查经过审查的更新，以及已经不再值得保留的技能。
- **路由器**（每次请求前运行的钩子）判断这个请求属于哪类工作（修 bug、做计划、做评审、慢查询），说出为这类工作而写的已安装技能，并让代理决定是否使用。没有合适的就什么也不说。它在你的电脑上运行，大约十分之一秒，只会把技能名称写进代理的上下文。它能理解英文和土耳其文的请求。

两个钩子都由你自己开启：`repotify enable repotify-tracker repotify-router`。

## 目录是怎样建立的

代理只看一行描述来挑选技能。Repotify 会先读完整个技能，以及人们对它的评价。

1. **发现。** 爬虫把一个仓库的每个技能文件夹抓取一次，存入内容库：目前来自 54 个仓库的 4,651 个技能文件夹。MCP 服务器来自官方 MCP 注册表：36,000 多个服务器中，有 13,547 个可以通过 npm 或 PyPI 在本地安装。
2. **审查。** 每个文件都按 shell 的方式解读（隐藏下载、窃取凭据、提示注入）。对于 MCP 服务器，会检查目录固定的那个版本的安装脚本和已知漏洞，并且软件包必须有能启动服务器的命令。
3. **分类。** 一个决策模型（[Jev](https://openrouter.ai/docs/guides/community/jev)）读取每个技能完整的 `SKILL.md`，用概率回答这些问题：它是否属于软件工作、唯一的主要职责是什么、面向哪种语言、框架或产品、是否绑定某个产品、用途是什么、是一次性有用还是每次都有用、质量如何。规则只依据有把握的回答行动，其余交给人工。在 49 个人工标注的技能上：主要职责正确率 88%（评审团自由标注为 52%），语言 98%（86%），识别离题 98%（88%）。
4. **调研。** 星标可以买，所以四个调研代理会去读关于一个仓库的其他信息：论坛讨论、星标历史与真实安装量的对比、各类目录和精选列表。在调研的 90 个仓库中，有 19 个看起来星标虚高；其中三个仓库的技能（471 个）没有进入目录，而是等待人工查看。
5. **决定。** 规则在不联网、不调用模型的情况下把这些信息变成目录条目，所以改一条规则，目录几秒钟就能重建，不必重新下载或询问。431 个爬取到的技能和 24 个 MCP 服务器通过了规则，加入了 93 个人工审查过的条目。爬取到的条目只有在有真实使用证据（安装量，或下载量加上有人加星的仓库）时才进入默认集合，其余作为备选列出。
6. **挑选。** 由项目的清单文件决定需要哪些职责。每项职责一个经过审查的条目，控制在上下文预算内；人工挑选的优先。已经安装的保持原位。

模型只在构建目录时运行，你不需要 API 密钥，也没有模型调用：`repotify recommend` 是确定性的，可以离线运行。

## 为什么选择 Repotify

- **适合你的项目。** 依赖中有 Excel，就只带来表格技能，而不是 Word 和 PowerPoint。移动应用不会收到仅限 Web 的技能。
- **可疑内容进不来。** 每个技能都按 shell 和 curl 的方式解读，隐藏下载、窃取凭据和提示注入等已知手法都会被发现。
- **不臃肿。** 每项工作一个条目，控制在上下文预算内，代理保持快速。

## 清理已安装的技能

`repotify audit` 检查项目中已有的技能，告诉你哪些该保留、哪些该删除，并给出理由和每个技能的 token 开销。它也会读取代理已配置的 MCP 服务器：命令未通过安全扫描的标记为移除，版本没有固定或在配置文件里写了密钥的标记为复查。它不会删除任何东西。

有些技能只在一次性任务中有用：代码库地图在第一天很有价值，之后却在每次会话中加载描述、每次触发时加载全部指令。分类器会标记这类技能（候选表中的 ⏳），两周后 `audit` 会告诉你它已经完成了任务。

## 命令

| 命令 | 作用 |
|---|---|
| `repotify` | 读取项目并为你的代理安装 repotify 技能 |
| `repotify recommend` | 显示这个项目的推荐 |
| `repotify questions` | 只列出答案会改变推荐结果的问题 |
| `repotify ui` | 在本地页面上把决策画成一棵树 |
| `repotify install <id…> --yes` | 安装你选择的技能 |
| `repotify enable <id>` | 在展示改动后开启钩子或 MCP 服务器 |
| `repotify audit` | 评估已安装的技能和 MCP 服务器 |
| `repotify track` | 说明项目有什么变化，以及哪些新的选择适合 |
| `repotify suggest` | 把你自己的技能推荐到目录 |

支持 **Claude Code**、**Cursor**、**Codex**、**Gemini CLI** 以及任何读取 `.agents/skills` 的代理。全部命令、安全模型和隐私说明：[docs/GUIDE.md](../GUIDE.md)（英文）。

## 路线图

- [x] 审计已安装的技能、基于证据的推荐、支持 Linux、macOS 和 Windows
- [x] 每个技能都由决策模型分类：主要职责、语言、生命周期、离题筛查
- [x] 一次性有用的技能在完成任务后会被标记
- [x] 网站，每个技能都有评论区
- [x] 由爬取构建的目录：每个技能抓取一次、分类，并在星标之外做调研
- [x] 来自官方注册表、按真实使用情况挑选的 MCP 服务器
- [x] 只问会改变推荐结果的问题；把决策画成一棵树（`repotify ui`）
- [x] 让配置保持更新、并把代理指向合适技能的钩子
- [ ] 在数千个仓库上不间断运行的爬取
- [ ] 根据开发者保留和移除的内容不断优化排名（度量和学习模块已经完成；收集服务器尚未上线）
- [ ] MCP 模式：你的代理把 Repotify 当作工具调用
